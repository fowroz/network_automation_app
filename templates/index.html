🔎 Read-Only Inventory & Compliance Audit
? Audit vs. Run

▶ Run executes commands and can change device configuration (with explicit confirmation). It's the "Act" side.

🔍 Audit only ever reads data from devices via a declarative Audit Profile (a YAML list of fields to collect) — it can never enter configuration mode. It's the "Observe" side.

Both can target the same saved Inventories and share run history (see the Overview tab's merged Recent Activity feed).

Run a read-only Audit Profile (a YAML manifest declaring exactly which commands to send and which fields to extract — see audit_profiles/) against an Audit Target (a saved Inventory, or a device list typed below). Nothing here ever changes device configuration — every command an Audit Profile can send is a "show"-style read command by design.

🛟 Rollback Safety Net

Every config-mode run on the Run tab automatically snapshots each device's FULL running-config immediately before applying any changes. If a change turns out to be bad, use Rollback here to re-push that snapshot back to the device. This is a best-effort replay (line-by-line through config mode), not an atomic/transactional rollback — always review the resulting live log / diff afterward, especially on platforms without a true rollback primitive.
